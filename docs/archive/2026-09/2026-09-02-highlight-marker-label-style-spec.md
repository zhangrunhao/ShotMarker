# ShotMarker 1.3 片段序数标识样式规格

- 日期：2026-09-02
- 状态：已实现并完成自动验证；VoiceOver 与独立横屏流程待用户人工验收
- 目标版本：1.3

## 背景

当前集锦导出会为每个片段绘制 `number/total` 形式的序数标识；合并片段使用 `start-end/total`。现有实现由 `VideoClipSegmentPlanner` 生成文字，由 `VideoClipEditingService` 使用固定字号、固定左上位置、100% 不透明白字和 100% 不透明黑色圆角底绘制。

现有 `ClipSettings` 只保存打点前后时长，但它已经同时承担用户默认设置和 `HighlightJob` 任务快照。1.3 在这条现有数据链路中加入序数标识样式，使用户能在创建集锦前用真实视频缩略图预览并调整样式，而且排队后的任务不受后续设置变化影响。

## 已确认产品决定

- 序数标识使用一组全局样式，应用到一个集锦的所有片段。
- 位置通过拖动序数标识调整，不为每个片段单独设置。
- 预览使用第一个已选视频的真实静态缩略图。
- 预览不播放视频，也不提供时间轴或拖动进度。
- 文字和黑色圆角底的不透明度分开调整。
- 1.3 默认文字不透明度为 100%，默认黑底不透明度为 60%。
- 工程产品版本更新为 1.3；本 Change 不改变现有构建号。

## 目标

1. 用户选择至少一个视频后，可以看到序数标识在第一个已选视频缩略图上的实际预览。
2. 用户可以拖动标识、调整文字大小，并分别调整文字与黑底的不透明度。
3. 预览设置与导出结果使用同一套归一化数据语义。
4. 标识在任何受支持画面尺寸中都完整留在画面内。
5. 设置自动保存，并在创建任务时固化到 `HighlightJob`。
6. 1.2 保存的剪辑设置和集锦任务可以在 1.3 正常解码。

## 非目标

- 不支持每个片段分别设置样式或位置。
- 不增加视频播放、暂停、时间轴或逐帧预览。
- 不增加字体、文字颜色、背景颜色、圆角或内边距选择。
- 不增加独立的显示/隐藏开关；用户可以把两种不透明度都设为 0% 来隐藏标识。
- 不允许修改已经创建的任务，也不重新渲染已经完成的集锦。
- 不改变序数文字规则；单片段仍为 `number/total`，合并片段仍为 `start-end/total`。
- 不改变片段规划、合并、音频、视频方向或照片保存规则。
- 不处理现有多源视频方向与画幅差异之外的新剪辑能力。
- 不在 Apple Watch 上增加对应设置。
- 不增加 Analytics 事件或远端数据字段。

## 用户界面

### 出现位置

`TrainingSessionHighlightView` 保留现有训练摘要、剪辑范围、视频选择和生成流程。在“已选视频”之后、“覆盖结果”之前增加“片段序数”设置区。

- 没有已选视频时，不显示该设置区。
- 有已选视频时，设置区使用 `selectedVideoItems` 中第一项的缩略图，不因后续可用性排序而切换预览视频。
- 用户重新排序或重新选择导致第一项变化时，预览图随之变化，已保存样式数值保持不变。
- 创建任务期间，设置区和现有剪辑范围控件一起禁用。

### 静态真实画面预览

- 预览使用选择视频阶段已经取得的 `thumbnailData`，不得为了预览额外请求、下载或解码完整视频。
- 缩略图以完整画面比例显示，不裁掉横屏或竖屏内容；剩余区域使用黑色背景填充。
- 相册视频缩略图加载需要保留完整画幅，不能只保留现有 `aspectFill` 裁切结果。
- 如果第一项没有可用缩略图，显示相同交互区域的中性占位画面和“暂时无法显示视频预览”提示。拖动和三个调节项仍然可用，不阻止生成任务。
- 预览文字优先使用当前规划的第一个片段标签；当前没有可生成片段时显示示例 `1/1`。

### 拖动交互

- 用户直接拖动预览中的序数标识调整位置。
- 拖动位置表示标识中心点在完整视频画面中的归一化坐标。
- 坐标原点在画面左上角，`x` 向右增加，`y` 向下增加。
- `x` 和 `y` 的持久化范围都是 `0...1`。
- 拖动过程中根据当前预览标识的实际尺寸限制中心点，使整个标识留在画面内。
- 用户把标识拖到边缘时，不增加额外隐藏安全区；限制只负责防止标识超出画面。
- 导出标签可能比预览标签更长。若同一个中心点会令更长标签越界，导出时只把该标签向画面内移动到最近合法位置。
- 全局归一化位置应用到所有片段，不为不同标签保存不同坐标。

### 调节项

设置区提供以下三个调节项，并显示当前百分比：

| 调节项 | 范围 | 步长 | 默认值 | 语义 |
| --- | --- | --- | --- | --- |
| 文字大小 | 画面短边的 4%–16% | 1 个百分点 | 10% | 导出字体大小相对于完整视频画面短边的比例 |
| 文字不透明度 | 0%–100% | 5 个百分点 | 100% | 0% 完全透明，100% 完全不透明 |
| 黑底不透明度 | 0%–100% | 5 个百分点 | 60% | 0% 完全透明，100% 完全不透明 |

文字不透明度只影响白色文字；黑底不透明度只影响黑色圆角底。一个值不得隐式改变另一个值。

### 默认位置

默认位置延续现有左上角视觉意图，使用中心点归一化坐标：

- `x = 0.15`
- `y = 0.10`

如果默认中心点因具体标签尺寸或画幅而越界，预览和导出都使用最近合法位置，但不改写持久化的默认值。

### 辅助功能

- 三个调节项必须提供可读名称、当前百分比和值域语义。
- 拖动标识的辅助功能名称为“片段序数位置”，提示其作用于所有片段。
- 除触摸拖动外，标识提供“向左移动”“向右移动”“向上移动”“向下移动”四个 VoiceOver 自定义操作，每次移动对应轴的 5 个百分点并执行相同边界限制。
- 占位预览必须让辅助技术读出无法显示真实缩略图，但不能把它报告为功能错误。

## 数据模型

### MarkerLabelStyle

新增可编码、可比较的值类型 `MarkerLabelStyle`，使用 `Double` 保存以下字段：

~~~swift
struct MarkerLabelStyle: Codable, Equatable {
    var fontSizeRatio: Double
    var normalizedCenterX: Double
    var normalizedCenterY: Double
    var textOpacity: Double
    var backgroundOpacity: Double
}
~~~

默认值为：

~~~text
fontSizeRatio = 0.10
normalizedCenterX = 0.15
normalizedCenterY = 0.10
textOpacity = 1.00
backgroundOpacity = 0.60
~~~

有效范围为：

- `fontSizeRatio`：`0.04...0.16`
- `normalizedCenterX`：`0...1`
- `normalizedCenterY`：`0...1`
- `textOpacity`：`0...1`
- `backgroundOpacity`：`0...1`

模型需要提供统一的规范化逻辑。有限但越界的值夹取到最近边界；非有限值回退到对应默认值。设置加载、保存、任务创建、预览和导出都不得各自定义不同的范围规则。

### ClipSettings

`ClipSettings` 新增：

~~~swift
var markerLabelStyle: MarkerLabelStyle
~~~

`ClipSettings.default` 使用现有 9 秒前、4 秒后设置和上述 `MarkerLabelStyle.default`。

`ClipSettings` 继续作为：

1. `ClipSettingsStore` 中跨页面保存的用户默认设置；
2. `HighlightJob` 中创建任务时固化的完整剪辑设置快照。

不新增第二套序数样式存储，也不在 `HighlightJob` 顶层重复字段。

## 旧数据兼容

### 1.2 ClipSettings

1.2 JSON 只包含：

~~~json
{
  "secondsBeforeMarker": 9,
  "secondsAfterMarker": 4
}
~~~

1.3 解码该结构时必须保留原有两个时长，并补入 `MarkerLabelStyle.default`。不得因为缺少新字段而把整份设置丢弃为默认时长。

### 1.2 HighlightJob

1.2 `HighlightJob` 内嵌旧版 `clipSettings`。1.3 必须能加载这些任务，并为其补入默认序数样式：

- 未完成且可重启的旧任务使用 1.3 默认样式生成。
- 已完成旧任务的现有输出文件不变。
- 重新保存任务时可以写入完整的 1.3 `clipSettings`。

### 部分字段兼容

`MarkerLabelStyle` 自身使用逐字段的向后兼容解码。未来或损坏较轻的数据缺少单个字段时，只回退该字段，不覆盖其他可用字段。字段类型错误导致无法安全解码时沿用现有存储错误处理，不静默猜测字符串或其他类型。

## 任务与数据流

~~~text
首个已选视频 thumbnailData
        ↓
MarkerLabelSettingsView 预览与拖动
        ↓
ClipSettings.markerLabelStyle
        ├─→ ClipSettingsStore 自动保存为下次默认值
        └─→ HighlightJobManager.createJob
                    ↓ 任务快照
              HighlightJob.clipSettings
                    ↓
              HighlightJobRunner
                    ↓
              VideoClipEditingService
                    ↓
              导出视频序数标识
~~~

- 现有 `TrainingSessionHighlightView.onChange(of: clipSettings)` 继续负责自动保存。
- `HighlightJobManager.createJob` 继续接收完整 `ClipSettings`，无需新增平行参数。
- `HighlightJobRunner` 必须把任务快照中的 `markerLabelStyle` 明确传给导出闭包。
- `VideoClipEditingService.makeHighlightClip` 必须接收具体样式；生产调用不得在服务内部重新读取 `ClipSettingsStore`。
- 任务创建后再修改全局设置，不得影响 queued、running、interrupted 或 restarted 任务。

## 组件边界

### MarkerLabelSettingsView

新增独立 SwiftUI 组件，避免继续扩大当前已经较大的 `TrainingSessionHighlightView`。该组件负责：

- 显示真实缩略图或占位画面；
- 显示当前序数文字；
- 将拖动位置和视图几何转换为归一化中心坐标；
- 提供三个调节项和辅助功能操作；
- 通过 `Binding<MarkerLabelStyle>` 回写设置。

该组件不负责加载视频、不读取照片库、不持久化设置、不创建任务，也不包含 AVFoundation 导出逻辑。

### MarkerLabelLayout

提取无 UI 状态的布局计算，使预览与导出共享以下语义并可单元测试：

- 规范化数值；
- 归一化中心点与实际画面坐标互转；
- 按标识尺寸把原点限制在画面范围内；
- 把左上原点的预览坐标转换为 Core Image 左下原点坐标。

SwiftUI 与 Core Image 可以使用不同坐标类型，但不得复制两套互相独立的定位公式。

### TrainingSessionHighlightView

父页面只负责：

- 选择第一项缩略图和预览标签；
- 决定设置区是否显示和是否禁用；
- 把 `clipSettings.markerLabelStyle` Binding 传给子组件。

现有视频选择、准备、覆盖计算和任务创建行为保持不变。

## 导出渲染

- 保留现有白色等宽数字粗体、黑色圆角底、水平/垂直内边距和序数文字内容。
- 字体点数由最终渲染画面的短边乘以 `fontSizeRatio` 得出。
- 有效渲染画面的宽和高必须是有限正数；有效画面不再叠加绝对最小或最大字号限制。无法取得有效画面尺寸时沿用现有视频轨道错误路径，不用猜测尺寸继续导出。
- 白色文字使用 `textOpacity`。
- 黑色圆角底使用 `backgroundOpacity`。
- 标识图像先按样式绘制，再按归一化中心点放置。
- Core Image 的左下原点必须显式转换为产品定义的左上原点，保证预览向下拖动时导出结果也向下移动。
- 每种不同标签文字可以继续缓存一张标识图像；所有标签共享同一个任务样式。
- 每个标签按自己的实际宽高执行边界限制，因此较长标签在靠近边缘时允许比短标签更向内偏移。
- 当文字和黑底不透明度都为 0 时，导出结果中不显示标识；实现可以省略透明叠加层，但不得改变音视频时间线。

## 缩略图行为

- `PhotoLibraryVideoAssetProvider` 取得预览数据时使用完整画幅语义，不允许为了填满 16:9 卡片而永久裁掉竖屏内容。
- 现有已选视频卡片可以继续用 `scaledToFill` 视觉裁切；同一份图片数据在序数预览中使用 `scaledToFit`。
- 本地临时视频继续使用已应用 preferred transform 的 `AVAssetImageGenerator` 缩略图。
- 缩略图仍是选择阶段的轻量资源，预览不得把 `PHVideoRequestOptions.isNetworkAccessAllowed` 改为 `true`。

## 隐私、日志与 Analytics

- 序数样式只保存在本地 `UserDefaults` 和本地集锦任务 JSON 中。
- 不上传缩略图、样式、位置或透明度。
- 不新增 Analytics 事件。
- 现有任务创建日志可以继续记录片段数量和剪辑时长；不得为了本功能记录视频缩略图、原始图像数据或自由文本。
- 如需诊断样式传递，只允许记录有限枚举或规范化数字，不得加入视频内容信息；本 Change 默认不增加此类日志。

## 错误处理

- 缩略图缺失只影响真实画面预览，不得阻止样式调整或任务生成。
- 无可生成片段时使用 `1/1` 示例，不把预览状态误报为片段规划成功。
- 解码旧设置时缺少新字段属于正常兼容路径，不记录错误。
- 解码完整任务失败时沿用现有 `HighlightJobStore` 错误处理；本 Change 不引入部分恢复未知结构的机制。
- 导出前对任务样式再次规范化，防止手工修改或旧数据中的越界值导致标识丢失或 Core Graphics 计算异常。

## 测试要求

### 模型与持久化

- `MarkerLabelStyle.default` 的五个字段与本规格一致。
- 每个字段的有限越界值正确夹取，非有限值正确回退。
- 新版 `ClipSettings` 编解码往返保持样式。
- 1.2 `ClipSettings` fixture 解码后保留原有前后时长并获得默认样式。
- 缺少单个样式字段时只回退该字段。
- `ClipSettingsStore` 保存并恢复用户样式。
- 1.2 `HighlightJob` fixture 可以加载，并在嵌套设置中获得默认样式。
- 新版 `HighlightJobStore` 往返保持任务样式。

### 布局

- 左上、中心、右下归一化位置映射到正确的预览坐标。
- 左上原点与 Core Image 左下原点转换正确。
- 短标签在四边都不会越界。
- 长标签在同一中心点靠近边缘时向最近合法位置收敛。
- 横屏和竖屏画面使用同一归一化位置语义。
- 不同字号下边界限制使用实际标识尺寸。

### 任务快照

- `HighlightJobRunner` 把任务内样式原样传给导出闭包。
- 修改 `ClipSettingsStore` 后，已有任务仍使用创建时的样式。
- interrupted 任务重启时继续使用其持久化样式。

### 导出

- 自定义字号会改变最终绘制字号。
- 文字和背景不透明度分别应用，互不覆盖。
- 自定义归一化位置会改变叠加层原点。
- 两种不透明度都为 0 时仍能成功导出且无可见标识。
- 现有片段组合、方向、音轨、进度和取消测试继续通过。

### 界面与人工验收

由于仓库当前没有 UI Test target，至少完成以下 Simulator 人工验收并记录设备与系统版本：

1. 选择横屏视频，确认预览使用第一项真实完整缩略图。
2. 选择竖屏视频，确认画面不被裁成横屏缩略图。
3. 拖动到四个角和中心，确认预览标识不越界。
4. 分别调整文字大小、文字不透明度和黑底不透明度，确认预览即时变化。
5. 创建任务后修改默认设置，确认已创建任务的导出结果不变。
6. 导出包含短标签和合并长标签的集锦，确认位置与预览一致且完整可见。
7. 退出并重新进入生成页面，确认用户默认样式已恢复。

## 验收标准

1. 选择视频后出现“片段序数”设置区，并显示第一项视频的真实静态完整画面缩略图。
2. 用户可以直接拖动标识；保存、重新进入和最终导出使用同一全局归一化位置。
3. 用户可以在规定范围内调整字号，导出视觉大小随设置变化。
4. 用户可以分别调整文字和黑底不透明度；默认值分别为 100% 和 60%。
5. 所有标签在横屏、竖屏和不同文字长度下完整保留在画面内。
6. 一个任务的所有片段使用同一组样式，且任务创建后不受全局设置变化影响。
7. 1.2 剪辑设置和集锦任务可以加载，不因新增字段丢失原有时长或任务。
8. 预览不触发完整视频下载、播放或额外网络访问。
9. 现有视频规划、组合、进度、取消、保存和 Watch 功能没有回归。
10. iPhone 与随包 Watch App 的用户可见产品版本为 1.3，构建号保持不变。

# ShotMarker 项目进度文档设计

日期：2026-08-16

## 目标

把现有 `docs/current-codebase-status.md` 改造成 ShotMarker 的唯一内部项目状态页，供项目所有者和后续 Codex 任务快速了解当前进度、正在进行的工作、验证结果、风险与下一步。

该文档描述当前事实，不替代 PRD、功能设计、实施计划、提交历史或发布说明。

## 使用者与更新频率

- 主要使用者：项目所有者和参与后续任务的 Codex。
- 每完成一个功能或重要修复后更新。
- 准备发布、完成发布或发现重要阻塞时也必须更新。
- 小型格式调整、注释修改等不影响项目状态的变更无需更新。

## 方案

采用“当前状态 + 最近进展”的混合结构：

- 文档顶部始终呈现当前结论，允许读者在短时间内掌握项目状态。
- 文档底部只保留少量最近进展，帮助理解当前状态如何形成。
- 更早的历史不在正文长期累积，由 Git 历史保存。

不新增第二份平行状态文档，继续使用 `docs/current-codebase-status.md`，避免多个状态来源互相矛盾。

## 固定结构

正式状态页按以下顺序维护：

1. **文档元数据**
   - 最后更新时间。
   - 基准分支和提交。
   - 文档对应的工作区状态。
2. **总体状态**
   - 用数句话说明项目当前所处阶段。
   - 区分已完成、开发中和暂缓事项。
3. **已完成功能**
   - 按产品能力分组描述当前可用功能。
   - 只保留理解当前产品所需的信息。
4. **正在进行的工作**
   - 记录已经有代码、设计或未提交变更支撑的工作。
   - 标明尚未完成或尚未验证的部分。
5. **测试与构建状态**
   - 记录最近一次验证日期、命令范围和结果。
   - 明确区分全量测试、专项测试、Debug 构建和 Release 构建。
6. **风险与待确认事项**
   - 记录隐私、发布、外部服务、真机验证等当前风险。
   - 无法从仓库确认的外部状态必须标为“未确认”。
7. **下一步优先级**
   - 只列近期可执行事项，并按优先级排序。
8. **发布前检查项**
   - 汇总全量测试、真机验证、Archive、dSYM、TestFlight 和隐私声明等事项。
   - 使用未完成、已完成或暂缓等明确状态。
9. **最近进展**
   - 保留最近 5–10 个重要功能、修复或文档节点。
   - 每条包含日期、结论和相关提交；超出数量后删除最旧条目，由 Git 保存历史。
10. **维护规则**
    - 提醒后续维护者如何核实事实、更新基准和记录验证结果。

## 事实来源与可信度

状态页按以下优先级取证：

1. 当前代码和配置。
2. 实际执行的测试、构建或发布命令结果。
3. 已提交的设计、计划和 Git 提交。
4. 用户明确确认的外部状态。

不得仅根据旧文档推断当前状态。App Store、TestFlight、GlitchTip、服务器部署等会变化的外部状态，如果本次没有验证，应保留最后已知事实并明确标注验证日期或“当前未确认”。

## 更新流程

每次需要更新状态页时：

1. 确认当前分支、HEAD 和工作区状态。
2. 检查自上次基准以来的重要提交和相关设计文档。
3. 根据实际代码与验证结果更新当前状态。
4. 移除已经过期或与当前实现冲突的描述。
5. 更新最近进展，但不把文档写成完整 changelog。
6. 检查文档中的文件路径、版本号、提交号和测试结论。
7. 将状态页变更与对应功能一起提交，或使用独立的 `docs:` 提交。

## 首次迁移内容

首次重写 `docs/current-codebase-status.md` 时，应反映以下已知状态：

- iPhone 与 Apple Watch 的训练打点、同步、视频选择和集锦生成主链路已经具备。
- GlitchTip 原生崩溃和 `logger.error` 上报已完成，并已在 Project 4 中看到验证事件和业务错误事件。
- 性能监控未启用。
- 最小埋点功能仍在推进，应依据迁移时的最新提交和工作区重新确认完成范围。
- Privacy Manifest 的完成状态应依据迁移时的代码和测试重新确认。
- dSYM 自动上传、下一次 Archive、真机崩溃验证和下一次发布暂缓到埋点完成后统一处理。
- 旧文档中的 App Store 审核状态不得直接沿用，除非重新验证。

## 安全与隐私

- 文档可以记录 GlitchTip 项目地址和客户端 DSN 的配置状态。
- 不得记录 GlitchTip Auth Token、Apple 登录凭据、证书私钥或其他秘密。
- 不得粘贴真实用户数据、训练记录、视频路径或错误事件中的敏感内容。

## 验收标准

- 仓库中只有一份被指定为当前项目状态来源的文档。
- 读者无需查看 Git 历史即可分辨已完成、进行中、暂缓和下一步。
- 每条测试或构建结论都有范围与日期，不夸大专项验证结果。
- 过期的 App Store 结论被删除或标记为未确认。
- GlitchTip、埋点、隐私清单和发布准备的状态清晰可辨。
- 文档包含明确的更新触发条件和维护方法，后续 Codex 可以按同一口径持续更新。

# ShotMarker 集锦片段审核与范围调整规格

- 日期：2026-09-02
- 状态：设计已确认，尚未实现
- 目标版本：不绑定发布版本；本 Change 不修改版本号或构建号
- 设计基线：`codex/clip-confirmation` / `8c549f5`

## 背景

ShotMarker 当前在用户选择视频后，直接按全局 `ClipSettings` 为每个打点生成候选范围，同一视频内重叠或间隔不超过 1 秒的范围自动合并，然后创建持久化集锦任务。默认范围为打点前 9 秒、打点后 4 秒。用户可以修改全局前后时长，但不能在生成前检查每个最终片段、排除误打点或单独修正片段边界。

当前 `HighlightJob` 保存训练记录、所选视频和全局剪辑设置；`HighlightJobRunner` 运行任务时重新调用 `VideoClipSegmentPlanner`。如果后续加入只存在于界面内的逐片段调整，而任务不保存精确片段，排队、重启或中断恢复都会丢失用户确认的结果。

本 Change 在视频准备与任务创建之间加入片段审核阶段。审核单位是默认规划已经合并、真正可能成为导出结果的片段，例如 `1`、`2–3`、`7–9`，而不是要求用户逐个点击每个原始打点。

## 已确认产品决定

- 原始 `TrainingSession` 和 `ShotMarkerEvent.markedAt` 继续表达训练事实，审核与剪辑不得修改它们。
- 用户必须经过一次片段审核页，但不必逐张卡片执行机械式确认。
- 所有默认审核卡片初始为保留；用户只处理需要排除或调整的卡片。
- 审核页使用图集形式展示默认合并后的片段，卡片显示 `1`、`2–3`、`7–9` 等编号。
- 点击编号或卡片进入对应片段的独立编辑器。
- 合并卡片是第一版的原子审核单位；`2–3` 可以整体保留、排除和调整，但不能在该卡片内只排除 2 或只排除 3。
- 用户可以分别拖动片段左右边界，也可以保持长度不变地整体前后移动片段。
- 原始打点只作为编辑器中的固定参考线；调整后的片段允许不再包含参考线。
- 最终确认后，精确片段必须固化到 `HighlightJob`，任务运行与重启不得重新套用全局前后时长。
- 第一版不持久化尚未确认的审核草稿；用户实际使用后再决定是否需要跨 App 重启恢复。

## 目标

1. 用户可以在创建集锦任务前看到所有默认合并片段的图集总览。
2. 用户无需逐项点击即可沿用全部默认片段并继续生成。
3. 用户可以排除或恢复任意审核卡片，而且不会改变训练记录。
4. 用户可以播放单个片段，并以 0.1 秒保存精度调整起点、终点或整体位置。
5. 审核总览实时展示保留打点数、排除打点数、最终片段数和预计总时长。
6. 调整后重叠或间隔不超过 1 秒的相邻片段在最终确认时合并，导出不产生重复画面。
7. 新任务、排队任务、中断任务和重启任务都使用同一份已确认精确片段。
8. 现有 1.2、1.3 任务 JSON 继续可读，旧任务行为保持兼容。
9. 图集、时间轴、任务快照和导出不增加业务内容上传或新的 Analytics 事件。

## 非目标

- 不修改 Watch 打点、训练记录、同步载荷或训练 JSON 导入导出格式。
- 不支持拆开 `2–3` 等合并卡片内部的单个打点。
- 不支持用户重新排列片段顺序；最终顺序沿用默认审核图集的原始打点顺序。
- 不支持一张审核卡片跨越两个源视频。
- 不支持在任务创建后再次编辑片段或重新渲染已完成任务。
- 不持久化未确认的审核草稿，也不在 App 被终止后恢复草稿。
- 不增加逐帧编辑、可变速播放、转场、音量、裁切画幅或高级时间轴缩放。
- 不改变片段序数样式、音轨保留、视频方向或手动保存相册规则。
- 不增加 Apple Watch 界面、远端字段或 Analytics 事件。
- 不在本 Change 中修改产品版本号或构建号。

## 用户流程

1. 用户打开一条训练记录并选择一个或多个对应视频。
2. App 完成现有视频范围校验和必要的 iCloud 准备。
3. 用户设置全局默认剪辑范围和片段序数样式。
4. 当前“生成集锦”入口改为“下一步：审核片段”。
5. App 使用当前训练记录、可用视频和全局默认范围生成审核草稿。
6. 审核页展示默认合并后的图集卡片；所有可用卡片默认保留。
7. 用户可以直接确认默认结果，也可以排除卡片或进入单片段编辑器调整范围。
8. 审核页实时计算最终合并预览和预计总时长。
9. 用户点击“确认并生成”。
10. App 验证并规范化保留片段，把精确快照写入新的 `HighlightJob`。
11. 任务进入现有持久队列，页面返回首页；Runner 直接使用任务快照导出。

用户没有进入审核页时不能创建新式集锦任务，但进入后不要求逐张点击。页面级“确认并生成”代表用户接受所有当前保留状态和边界。

## 审核图集

### 布局与卡片内容

审核页使用适合 iPhone 宽度的双列图集；空间不足时可以退化为单列，不能通过缩小点击区域保持双列。每张卡片至少展示：

- 当前审核编号，例如 `1`、`2–3`、`7–9`；
- 当前片段的静态缩略图或占位图；
- 片段长度；
- 保留或已排除状态；
- 编辑入口。

编号使用独立、始终可见、至少 44×44 点的点击区域。整张卡片也可以进入编辑器，避免只有小编号可以操作。卡片编号属于审核界面，不受导出序数文字透明度或位置设置影响。

缩略图取当前片段范围的中点。编辑完成后允许异步刷新缩略图；刷新期间保留旧图或占位图，不能清空用户调整。缩略图以完整画幅显示，竖屏视频使用黑色填充而不是裁掉内容。

### 默认状态与排除

- 所有可读取的默认卡片初始 `isIncluded = true`。
- 用户排除卡片时，该卡片变灰并显示“已排除”，但仍留在原位置并可恢复。
- 排除合并卡片会排除它关联的全部打点；原始打点和训练记录保持不变。
- 被排除卡片保留已经做过的范围调整；恢复后继续使用该范围，而不是自动重置。
- 不可读取的卡片不是自动排除。它显示明确错误，用户必须排除它或返回重新选择视频。

### 编号

卡片身份由稳定 ID 和关联打点 ID 决定，不能使用可变化的展示编号作为数据身份。

初始编号沿用当前规划语义：只对被所选视频覆盖的匹配打点按时间排序并编号，合并卡片显示连续范围。未匹配打点继续显示在覆盖结果中，不进入审核图集。

排除或恢复卡片后，保留打点按图集原始顺序重新连续编号，分母为当前保留打点总数。被排除卡片保留灰色的原始审核编号，方便用户识别和恢复。编号变化不得改变卡片顺序、稳定 ID 或已编辑范围。

### 汇总

审核页必须实时展示：

- 保留打点数；
- 排除打点数；
- 规范化后最终输出片段数；
- 最终预计总时长。

如果调整后的相邻卡片会在生成时合并，对应卡片和汇总区域显示“生成时将合并”。编辑期间不直接删除或折叠卡片，避免正在操作的卡片突然消失。

没有任何有效保留片段时，“确认并生成”禁用，并说明至少需要保留一个可用片段。

## 单片段编辑器

### 页面组成

编辑器标题使用当前审核编号，例如“片段 2–3”。页面由以下区域组成：

1. 当前源视频的播放预览；
2. 当前视频时间码、起止时间和片段总长度；
3. 局部胶片时间轴；
4. 起点手柄、终点手柄、整体移动抓手和播放游标；
5. 0.5 秒精调控件；
6. 保留状态与“恢复默认范围”。

编辑自动写回本次审核草稿。返回图集不需要第二次保存；“恢复默认范围”只重置当前卡片到首次生成审核草稿时的起止范围，不影响保留状态或其他卡片。

### 播放

- 播放器默认停在当前片段起点，不自动播放。
- 点击播放只播放当前选中范围，到终点后暂停并回到起点，方便再次检查。
- 调整起点时暂停并预览新起点；调整终点时暂停并预览终点前的可用画面；整体移动后暂停并回到新起点。
- 用户拖动独立播放游标可以在当前局部时间轴中浏览，但游标不改变片段范围。
- 视频没有音轨时仍可审核；存在音轨时正常播放。

### 局部时间轴

整场训练视频可能持续数十分钟，第一版不把整段视频压缩成一个不可操作的细条。时间轴使用当前片段范围加前后上下文的局部窗口：

- 目标窗口长度为 `max(当前片段长度 + 10 秒, 20 秒)`；
- 初始窗口以当前片段为中心，优先在两侧各保留 5 秒，再把额外空间平均分配到两侧；
- 到达视频开头或结尾时，把无法使用的单侧空间移到另一侧；来源视频本身短于目标窗口时显示完整视频；
- 整体移动接近窗口边缘时，窗口随当前片段自动平移；
- 第一版不提供捏合缩放。

时间轴使用均匀抽取的本地视频帧形成胶片。帧生成异步、可取消并按当前卡片缓存；生成失败显示中性占位格，但只要视频仍可播放就不阻止编辑。

每个关联原始打点以固定参考线显示，并标出其审核序号。参考线永远来自原始 `markedAt` 映射，不随片段移动。片段整体移动后允许参考线位于选中范围之外；这表示用户用原始打点定位后选择了更合适的画面，不表示训练数据被修改。

### 手势与精调

- 拖动左手柄只改变起点。
- 拖动右手柄只改变终点。
- 拖动选中区间中央的明确抓手时，保持当前长度不变并整体移动。
- 点击时间轴空白区域或拖动独立播放游标只预览，不移动范围。
- 手柄、整体抓手和播放游标必须在视觉和辅助功能语义上区分，不能依靠同一片区域猜测用户意图。
- 触摸拖动结果按 0.1 秒规范化并保存。
- 起点和终点各提供 0.5 秒步长的减少、增加操作。
- 整体范围提供向前 0.5 秒、向后 0.5 秒操作。

“向前”表示更早的视频时间，“向后”表示更晚的视频时间；界面同时显示 `-0.5s`、`+0.5s` 或方向图标与文字，避免只使用有歧义的中文方向词。

## 时间语义与范围约束

审核和任务快照都使用相对于来源视频开头的 `TimeInterval`：

- `start`：片段起点秒数；
- `duration`：片段长度；
- `end = start + duration`。

所有值必须有限，并满足：

~~~text
0 <= start
0 < duration
end <= sourceVideo.duration
duration >= min(1.0, sourceVideo.duration)
~~~

规则如下：

- 左右手柄不能交叉。
- 视频长度至少 1 秒时，片段最短为 1 秒；更短的有效视频只能使用其完整可用范围。
- 第一版不设置独立最大片段长度，最大值由来源视频边界决定。
- 整体移动到视频边界时夹取位置并保持片段长度不变。
- 单边手柄到达视频边界或最短长度时停止。
- 0.1 秒值使用导出 timescale 600 表示，不能在界面、任务和导出间使用不同舍入规则。
- 一张卡片只能引用一个 `videoID`，也只能在该视频的时间范围内移动。
- 调整不提供片段排序能力；最终导出顺序保持审核图集的原始顺序。

## 默认审核规划

`VideoClipSegmentPlanner` 的第一阶段从现有输入生成审核草稿：

1. 按 `markedAt` 排序训练打点。
2. 为每个打点选择第一个覆盖该时间的已选视频，沿用当前选择顺序规则。
3. 使用当前 `ClipSettings.secondsBeforeMarker` 和 `secondsAfterMarker` 生成默认范围。
4. 把范围裁剪到来源视频边界，丢弃非正长度结果。
5. 仅对匹配成功的打点连续编号。
6. 对同一视频内重叠或间隔不超过 1 秒的相邻范围执行现有合并规则。
7. 每个合并结果生成一张审核卡片，保存全部关联打点引用和默认范围。

因此用户完全不调整并保留全部卡片时，最终画面范围和现有规划结果一致。本 Change 不能让“直接接受默认审核结果”产生与旧逻辑不同的剪辑范围。

## 最终确认与合并

`VideoClipSegmentPlanner` 的第二阶段把审核草稿转成最终片段：

1. 保留图集原始顺序，过滤 `isIncluded = false` 的卡片。
2. 验证每张保留卡片的来源视频和范围，并应用统一 0.1 秒规范化。
3. 按保留卡片顺序为关联打点重新连续编号。
4. 对相邻、同一视频且实际区间重叠或区间距离不超过 1 秒的保留卡片进行最终合并。
5. 合并范围取所有成员范围的并集，关联打点取有序并集。
6. 生成最终 `markerNumberLowerBound`、`markerNumberUpperBound` 和 `markerTotalCount`。
7. 计算最终片段数和总时长，交给页面汇总与任务创建共同使用。

区间距离按两个区间的真实位置计算，不能假设后一个已编辑区间的起点一定晚于前一个：

~~~text
gap = max(0, max(lhs.start, rhs.start) - min(lhs.end, rhs.end))
merge when gap <= 1 second
~~~

最终合并只发生在图集顺序相邻的卡片之间，避免用户没有获得重新排序能力时跨过其他片段改变输出顺序。一个合并结果可以覆盖多张审核卡片，但这些卡片在确认前仍保持独立可编辑。

## 数据模型

### 审核草稿

审核草稿是生成流程内的可变状态，不写入训练记录或全局设置。模型语义至少包含：

~~~swift
struct HighlightClipMarkerReference: Identifiable, Equatable {
    let id: UUID
    let markedAt: Date
    let timeInVideo: TimeInterval
    let originalMatchedNumber: Int
}

struct HighlightClipReviewItem: Identifiable, Equatable {
    let id: UUID
    let videoID: String
    let markerReferences: [HighlightClipMarkerReference]
    let defaultStart: TimeInterval
    let defaultDuration: TimeInterval
    var start: TimeInterval
    var duration: TimeInterval
    var isIncluded: Bool
}
~~~

具体类型名可以在实施计划中按工程风格调整，但必须保持以下边界：

- 稳定 ID 与展示编号分离；
- 默认范围与当前范围分离，以支持恢复默认；
- 打点引用足以绘制固定参考线并在最终确认后重新编号；
- 草稿不持有 `AVAsset`、`AVPlayer`、缩略图二进制或其他不可比较的运行对象。

### 任务精确片段

新增可编码、可比较的任务快照值类型，语义至少包含：

~~~swift
struct ConfirmedHighlightSegment: Codable, Equatable {
    let id: UUID
    let videoID: String
    let markerIDs: [UUID]
    let start: TimeInterval
    let duration: TimeInterval
    let markerNumberLowerBound: Int
    let markerNumberUpperBound: Int
    let markerTotalCount: Int
}
~~~

`HighlightJob` 新增：

~~~swift
var clipPlanVersion: Int?
var confirmedSegments: [ConfirmedHighlightSegment]?
~~~

新任务必须同时保存 `clipPlanVersion = 1` 和非空 `confirmedSegments`。两个字段使用可选类型只为兼容旧 JSON；运行时必须把版本字段作为判别依据，不能只根据片段数组是否存在猜测任务类型。

- `clipPlanVersion == nil && confirmedSegments == nil`：没有两个新字段的 1.2/1.3 旧任务，使用旧兼容规划。
- `clipPlanVersion == nil && confirmedSegments != nil`：不一致数据，明确失败。
- `clipPlanVersion == 1`：新任务，必须存在非空且通过验证的 `confirmedSegments`。
- 未知版本：任务数据错误，不能尝试按已知结构生成。

任务快照保存所有导出和重启需要的精确范围与标签语义。`ClipSettings` 继续保存在任务中，负责序数样式及旧任务兼容，但不再决定新任务的片段起止时间。

## 任务创建与运行

`HighlightJobManager.createJob` 接收已确认片段，并在入队前执行以下检查：

- 最终片段非空；
- 所有值有限且满足视频边界与最短长度；
- 每个 `videoID` 都能在当前选择中找到；
- 每个片段至少关联一个打点；
- 编号范围和总数一致。

任务只保留最终片段实际引用的来源视频。对于通过 PhotosPicker 产生的本地临时文件，只复制仍被保留片段引用的文件，避免为全部排除的视频创建无用任务输入。

`HighlightJobRunner` 的行为分为：

- `clipPlanVersion == 1`：验证 `confirmedSegments` 后直接传给 `VideoClipEditingService`，不得调用默认规划重新计算范围。
- 两个新字段都为 `nil`：继续使用 `trainingSession + selectedVideos + clipSettings` 调用旧兼容规划。
- 没有版本但存在快照：明确失败。
- 版本未知、版本 1 缺少快照或快照无效：明确失败，不回退旧规划。

取消、重启、中断恢复和 App 启动恢复都保留 `confirmedSegments`。修改之后的全局剪辑范围或序数样式不得改写已经创建的任务。

## 旧数据兼容

### 旧 HighlightJob

1.2 和 1.3 任务 JSON 没有 `clipPlanVersion` 和 `confirmedSegments`。解码时两个字段均为 `nil`，其他字段保持原值：

- 未完成且允许重启的旧任务继续按其内嵌 `ClipSettings` 规划；
- 已完成任务的输出文件不变；
- 重新保存旧任务时允许继续省略两个字段或编码为 `null`，不能伪造版本 1 或一份未经用户确认的快照。

### 新 HighlightJob

版本 1 新任务的 `confirmedSegments` 缺失、为空或损坏，以及任务声明未知 `clipPlanVersion` 时，都属于任务数据错误，不得静默回退到默认规划。Runner 必须失败并显示可操作的重新创建任务提示，避免生成与用户确认不一致的视频。

### TrainingSession 与 ClipSettings

本 Change 不改变 `TrainingSession`、`ShotMarkerEvent`、Watch 同步载荷或 `ClipSettingsStore` 编码。旧训练记录和现有默认设置不需要迁移。

## 组件边界

### HighlightClipReviewPlanning

无 UI 状态的规划单元，负责：

- 生成默认审核卡片；
- 规范化单卡片边界；
- 从审核草稿生成最终合并片段；
- 计算重新编号、预计总时长和合并提示；
- 验证任务精确片段。

该逻辑可以在 `VideoClipSegmentPlanner` 内分阶段实现，也可以提取为相邻的专用类型；实施计划必须避免在 SwiftUI View 中复制合并和编号规则。

### HighlightClipReviewViewModel

`@MainActor` 状态单元，负责：

- 持有审核草稿和当前编辑卡片；
- 排除、恢复、调整和恢复默认；
- 调用规划单元取得实时汇总；
- 协调按需缩略图与播放器资源；
- 处理退出或草稿失效确认。

它不写训练记录、不直接导出视频，也不自行定义时间范围规则。

### HighlightClipReviewView

负责图集、汇总、错误状态和“确认并生成”。它从 ViewModel 读取展示状态，通过稳定卡片 ID 发出用户意图，不持有 AVFoundation 导出逻辑。

### HighlightClipEditorView 与 HighlightClipTimelineView

编辑器负责组合播放预览、时间值、精调和保留状态。时间轴组件负责把局部时间窗口映射为屏幕坐标，并把手势映射为起点、终点、整体移动或播放游标动作。

时间轴不读取照片库、不持久化任务，也不直接修改原始 `ShotMarkerEvent`。

### HighlightClipPlaybackController

按当前卡片加载一个来源视频，负责：

- 播放选中范围；
- 到达终点时暂停并回到起点；
- 响应范围变化和游标预览；
- 移除时间观察者、取消旧资源加载并释放非当前播放器项。

### TrainingSessionHighlightView

现有页面继续负责训练摘要、默认剪辑设置、视频选择与准备、序数样式和审核入口。新审核、时间轴和播放逻辑必须放入独立组件，不能继续扩大当前大型 View。

## 数据流

~~~text
TrainingSession + selectedVideos + ClipSettings
                    ↓
        默认审核规划与初次合并
                    ↓
        HighlightClipReviewViewModel
          ├─→ 图集缩略图与汇总
          └─→ 单片段播放与范围调整
                    ↓ 用户确认
        过滤、重新编号、最终合并
                    ↓
        ConfirmedHighlightSegment[]
                    ↓
        HighlightJobManager.createJob
                    ↓ 任务 JSON 快照
              HighlightJobRunner
                    ↓
          VideoClipEditingService
                    ↓
                本地 MOV
~~~

同一份最终规划结果必须同时驱动审核页汇总和任务创建，不能在按钮点击时使用另一套算法再次计算。

## 草稿生命周期

- 审核草稿只存在于本次生成流程内。
- 在图集与单片段编辑器之间切换时完整保留。
- 用户返回设置页但没有修改视频或全局剪辑范围时可以再次进入同一草稿。
- 用户修改视频选择、视频可用性或全局前后时长时，现有草稿失效；App 必须先提示，确认后才丢弃并重新生成。
- 修改片段序数样式不改变范围草稿，因为样式不参与片段规划。
- 用户主动退出整个生成流程且草稿包含调整或排除时，提示“放弃片段调整？”；确认后才退出。
- App 被系统终止后不恢复未确认草稿，这是第一版明确限制，不得描述为已保存。

## 错误处理

### 审核前

- 没有任何匹配打点：保留现有覆盖错误，不进入审核页。
- 视频仍在准备或读取失败：保留现有准备与重试流程，不生成半成品审核草稿。

### 审核中

- 缩略图帧生成失败：显示占位图，不自动排除；播放器可用时仍允许编辑和确认。
- 播放器暂时加载失败：显示重试入口，保留范围调整。
- 来源视频永久不可读或已删除：卡片标为不可用；用户可以排除或返回重新选择，不能以保留状态确认。
- 范围因为异常输入失效：显示卡片级错误并提供恢复默认，不静默生成零长度片段。

### 任务创建与运行

- 最终规划为空：不创建任务。
- 精确片段引用缺少来源视频：不创建任务并提示重新选择视频。
- 复制本地输入失败：沿用任务创建错误路径，审核草稿保持在页面中。
- 新任务快照损坏：Runner 失败并提示重新创建，不回退默认范围。
- 导出失败、取消和重启：沿用现有任务队列状态机，但重试使用相同精确片段。

## 性能与资源

- 图集缩略图按可见卡片懒加载，不一次性为所有长视频生成全部帧。
- 单片段胶片帧只覆盖当前局部时间窗口，窗口变化时取消不再需要的生成任务。
- 同一审核生命周期可以使用有上限的内存缓存；缓存键至少包含视频 ID、时间点和目标尺寸。
- 同一时刻只保留当前编辑卡片的活跃播放器项和时间观察者。
- 页面退出、卡片切换和视频选择变化时取消旧缩略图、播放器和资源请求。
- 性能优化不得改变视频是否需要用户确认下载的现有隐私与流量语义。

## 辅助功能

- 图集编号按钮和整张卡片都提供片段编号、时长、保留状态和“打开片段编辑”的可读语义。
- 被排除卡片明确读出“已排除”；不可用卡片明确读出原因。
- 左右手柄分别命名为“片段起点”和“片段终点”，读出当前视频时间码。
- 整体抓手命名为“移动整个片段”，读出当前起止时间和长度。
- 播放游标命名为“预览位置”，不能与剪辑范围手柄合并为一个元素。
- 所有拖动能力都有等价的 0.5 秒按钮或辅助功能调整操作。
- 边界限制、最短长度和无法继续调整时提供可理解反馈。
- 支持 Dynamic Type；文字放大时允许图集退化为单列，不能缩小点击区域或截断关键状态。
- 时间值使用等宽数字展示，但辅助技术读取为自然语言秒数或时间码。

## 日志、Analytics 与隐私

本 Change 不增加 Analytics 事件，继续维持现有四事件契约。

本地日志可以记录：

- 默认审核卡片数；
- 保留和排除的打点数；
- 最终片段数；
- 最终总时长；
- 是否发生最终合并；
- 缩略图、播放资源、验证和任务创建的错误类别。

日志不得记录视频帧、文件名、Photos local identifier、原始打点 UUID、训练 UUID、用户标识或视频音频内容。审核缩略图、时间范围、播放状态和任务精确片段不上传业务服务器。

## 自动测试

### 规划与模型

- 默认审核规划与当前旧规划产生相同范围和合并结果。
- 多视频仍使用第一个覆盖打点的已选视频。
- 未匹配打点不进入图集，匹配编号连续。
- `1`、`2–3`、`7–9` 等合并卡片保存正确打点引用。
- 卡片稳定 ID 不随排除、恢复或重新编号变化。
- 排除合并卡片会排除其全部关联打点。
- 恢复卡片保留此前调整。
- 排除后保留打点重新连续编号。
- 编辑后重叠或间隔不超过 1 秒的相邻卡片最终合并。
- 间隔大于 1 秒、不同视频或图集不相邻的卡片不合并。
- 最终总时长按合并后范围计算，不重复累计重叠部分。

### 时间范围

- 左右边界夹取到视频范围。
- 手柄不能交叉，最短长度规则正确。
- 视频短于 1 秒时使用完整有效范围。
- 整体移动在边界处保持长度。
- 拖动值按 0.1 秒规范化，精调值按 0.5 秒变化。
- 非有限或损坏值被验证拒绝。
- 恢复默认只影响当前卡片范围。
- 原始参考线时间不随任何调整变化。

### 任务与兼容

- 新任务 JSON 往返保留版本 1、精确片段、打点关联和编号。
- 1.2/1.3 fixture 缺少两个新字段时正常解码并使用旧规划。
- 版本 1 新任务缺少或损坏快照时明确失败，不回退旧规划。
- 缺少版本但意外存在快照时明确失败，不把不一致数据当成旧任务。
- 未知 `clipPlanVersion` 明确失败，不猜测其字段语义。
- 创建任务只复制最终片段引用的本地视频。
- 创建任务后修改全局默认设置不会改变任务片段。
- Runner、取消、重启和中断恢复都使用相同精确片段。
- 导出服务收到的起止时间和审核确认结果一致。

### ViewModel 与资源

- 排除、恢复、调整、恢复默认和汇总状态转换。
- 草稿在图集与编辑器切换时保留。
- 视频或全局时长变化触发草稿失效确认。
- 缩略图失败不阻止播放器可用的卡片。
- 来源永久不可用时阻止保留状态确认。
- 卡片切换会取消旧缩略图和播放器请求。

## 人工验收

使用至少一个横屏视频、一个竖屏视频和包含多个相邻打点的训练记录完成：

1. 选择视频后进入审核页，确认图集显示真实完整画幅缩略图和正确编号。
2. 不编辑任何卡片直接确认，验证结果与旧默认规划范围一致。
3. 排除并恢复普通卡片和合并卡片，验证状态、编号和汇总实时更新。
4. 点击 `1`、`2–3` 等编号进入正确编辑器。
5. 拖动左右手柄、整体抓手和播放游标，验证三种手势互不混淆。
6. 使用所有 0.5 秒精调操作，验证显示值和实际播放范围一致。
7. 把片段移动到视频开头和结尾，验证边界与最短长度。
8. 调整两个相邻卡片使其重叠，验证图集提示和最终合并结果。
9. 验证播放只在选中范围内进行，到终点后回到起点。
10. 验证多打点参考线保持固定，片段可以移动到参考线之外。
11. 修改序数样式后返回审核页，验证范围调整不丢失。
12. 尝试修改视频或全局前后时长，验证草稿失效确认。
13. 主动退出含调整的流程，验证放弃提示。
14. 模拟缩略图失败、无音轨视频和来源视频不可用。
15. 创建任务后修改全局设置并重启任务，验证导出仍使用确认范围。
16. 使用 VoiceOver 完成卡片进入、排除、手柄精调、整体移动、播放和恢复默认。
17. 使用最大 Dynamic Type，验证关键状态、时间值和点击区域仍可操作。

# 片段取景与连续审核

日期：2026-10-23

状态：2026-10-23 用户已批准完整规格并要求实施；尚未完成实现与验证。

代码依据：`ea470c1`。本文是设计规格，不是实施计划。

## 意图与范围

优先服务个人投篮训练。用户希望同一视频中的连续投篮沿用同一画面中心和放大倍数，换位置后调整一次即可继续审核。例如前八段使用 A / 2.2×，随后两段使用 B / 3×，后五段使用 C / 2.8×。

用户选择通过连续审核自然延续取景，无需先建立分组。取景属于具体片段，不建立组内实时联动关系。

### 用户已明确确认

- 删除编辑器顶部的“上一段”“下一段”，通过底部缩略图手动跳转。
- 只有点击保留或排除并成功自动进入下一段时，才传递当前取景。
- 手动跳转不传递离开片段的取景；目标片段有自己保存的取景则显示它自己的，没有则显示原画面。
- 提供“恢复原画面”，恢复完整画面与 1×；随后连续审核可以沿用这个状态。
- 可以调整取景中心与放大倍数，支持 2.2×、3×、2.8× 等实际需求。

### 完整规格已确认的默认值

1. 取景用于预览和最终导出。
2. 连续传递仅限同一源视频；跨视频按目标自身已保存取景或原画面打开。
3. 自动进入下一段时，即使目标已有已保存取景，也先展示刚传来的取景作为临时初始值；目标旧值仅在再次确认后被替换。手动重开仍取其已保存值。
4. 仅继承而未手动调整的初始值，不触发离开时的放弃提示；离开就丢弃。用户主动调整取景、范围或保留状态后，沿用现有未保存提示。
5. 第一版作用于现有审核片段；一个已合并片段中的多个打点共用取景，不新增按内部打点拆分的能力。
6. 第一版缩放范围 1–4×，步长 0.1×，保持源视频的完整画幅比例；不增加自由裁切比例、旋转、动画变焦或人物跟踪。
7. 两个独立审核片段取景不同时不合并。若原视频时间范围重叠，仍分别播放各片段的完整范围，允许重叠内容重播，不自动截断投篮动作。

用户已整体批准本规格；数学规范、状态传递和验证细节作为实现与验收依据。

## 已讨论的方式

| 方式 | 取舍 | 结论 |
| --- | --- | --- |
| 手动设置打点分组，每组共享取景 | 方便统一修改，但要求用户先选择组范围并理解组边界 | 初始建议，用户改选连续延续方式 |
| 保留/排除后向下一段传递取景，手动跳转独立恢复 | 符合顺着看、到新位置才调整的操作；无需维护组 | 用户选择的方向 |

具体采用每个片段保存取景快照、导航携带一次临时初始值的方式。回头修改一段不会自动改动其他已保存片段。

## 当前实现与改动边界

- `HighlightClipEditorView` 当前有顶部前后导航、时间轴和底部保留/排除；播放器固定在 16:9 容器内显示完整源画面。
- `HighlightClipReviewItem`、`PersistedHighlightTaskClip`、`ConfirmedHighlightSegment` 目前均没有取景字段。
- 自动确认和手动跳转目前共用 `.open(itemID:)`；新流程必须显式区分导航原因，不能靠一个全局“上次取景”推断。
- 默认规划已经把多个相近打点合并成审核片段；最终规划还会合并相邻且同源的保留片段。
- `HighlightTaskStore` 当前为 schema 1，并对未知高版本只读保护。任务配置写盘成功后才更新界面。
- 当前导出只为组成轨道设置一次来源方向，画面处理主要用于编号叠加。取景导出需逐来源处理方向，且必须独立于编号是否可见。
- 本次不改 Watch 打点、语音剪辑、时间轴拖动规则或源视频文件。

## 取景模型

新增值类型 `ClipFraming`，保存 `scale`、`centerX`、`centerY`，可编码、可比较、可用于渲染快照。

- 中心坐标针对应用视频方向变换后的完整源画面，左上角为 `(0, 0)`，右下角为 `(1, 1)`。
- 原画面为 `scale = 1`、中心 `(0.5, 0.5)`。
- 放大 s 倍时，取景矩形宽高分别为源画面的 `1/s`，保持源画面比例。
- 中心限制在 `[1/(2s), 1 - 1/(2s)]` 内，避免裁切范围越过画面边缘；1× 时中心固定。
- 统一纯几何逻辑处理归一化、范围限制、源视频方向和实际可显示区域；不能把播放器外部留黑也当成源画面放大。
- 输入缩放规范化到 0.1，中心规范化到十万分之一，之后做边缘限制；保存、比较、预览和导出使用同一结果。
- 非有限值或明显超范围的持久化值应校验失败，不能把损坏数据静默解释为另一取景；UI 手势越界则正常限制到边缘。

持久化片段增加可选 `framing`：缺失表示从未保存取景，显示原画面；显式的原画面值表示用户保存过 1×。两者显示效果相同，但须可在撤销时完整恢复。最终导出片段携带明确的有效取景。

## 导航与保存契约

### 打开方式

| 入口 | 初始取景 | 是否立即保存 |
| --- | --- | --- |
| 总览卡片、底部缩略图、“下一个未看”、退出后重开 | 目标已保存值，否则原画面 | 否 |
| 保留/排除成功后，同源紧邻下一段 | 刚保存的当前有效取景，作为目标临时初始值 | 否 |
| 保留/排除成功后，跨来源下一段 | 目标已保存值，否则原画面 | 否 |
| 撤销后打开被恢复片段 | 撤销恢复的已保存值，否则原画面 | 撤销事务先完成 |

传递只绑定本次自动导航的目标片段与来源，消费一次即结束。手动跳转、返回总览、撤销、来源变化、末项完成或关闭会话均不留下可供下次误用的传递状态。

### 工作副本

- 编辑器区分已保存快照、进入时的临时初始取景和用户主动修改；不得把继承值立即写入任务。
- 仅继承形成的预览差异不视为用户主动修改。提示可用简短“沿用上一段取景”，并保持可直接跳走。
- 用户缩放、移动画面或恢复原画面，只修改当前工作副本。主动修改后离开、跳转或撤销仍经过现有继续/放弃流程。
- 用户把所有主动修改改回进入时的值后，应消除相应未保存提示；不能永久记住“动过一次”。
- 放弃后不写任何目标取景，不恢复或传播已经离开的片段工作副本。

### 确认与撤销

- 保留或排除把当前时间范围、包含状态、确认状态和有效取景作为同一配置事务提交；排除也保存并传递取景。
- 验证 expectedRevision 和来源身份；先持久化，成功后才更新汇总、缩略图并自动导航。
- 失败时停留当前片段，保留全部调整，既不传递也不覆盖下一段。
- 最后一段保存后返回总览；没有额外向第一段传递或循环。
- 单级撤销恢复最近一次确认前的完整快照，包括取景缺失/显式原画面/放大值；撤销本身不产生继承。
- 保存、撤销和生成仍互斥。异步加载只能更新当前片段与当前加载代次，不能恢复先前取景；沿用已有同片段撤销时的加载失效保护。

## 操作与可访问性

- 删除顶部前后按钮及其单独一行，导航标题保留“片段 N / 总数”。底部缩略图仍能跳转并标明当前片段。
- 在视频有效画面上双指缩放、拖动平移。缩放围绕当前取景中心，移动用于调整中心；普通时间轴操作保持现状。
- 取景交互开始时暂停播放，结束后保持暂停，便于检查动作；用户可照常播放当前范围。
- 提供当前倍率读数和可调倍率控件，以便精确到 2.2×、2.8×；使用简短的“恢复原画面”操作。
- “恢复原画面”只复位空间取景；现有“恢复默认范围”只复位时间范围，两者互不影响。
- 不重新引入已移除的时间精调面板。倍率控件和移动动作提供 VoiceOver 替代操作及明确的边界反馈。
- 视频未载入或不可用时不接受取景手势；排除和手动导航仍沿用现有可用性规则。
- 总览与导航缩略图显示各片段已保存的取景；临时继承和未保存调整不批量改变其他缩略图。时间轴胶片保持完整源画面，用于定位时间。

具体控件布局、可访问性步进大小、提示的短文案由实施者确定，以不遮挡播放和主要审核操作为约束；不新增复杂设置页。

## 片段规划与导出

- 审核片段仍以 UUID 识别，候选编号和原始打点编号沿用现有规则。取景不改打点时间或片段起止。
- 最终合并须同时满足现有条件以及有效取景相等。缺失取景和显式原画面在合并判断中等价。
- 不同取景保留各自完整时间范围、独立输出片段及编号范围；重叠时间允许重复播放，汇总总时长必须按实际输出累加。
- 相邻关系提示继续显示实际重叠或间隔；因取景不同不合并时明确显示“取景不同，分别保留”，不能仍提示“生成时合并”。
- 源视频方向先归一化，再按取景矩形裁切，再映射到输出画布，最后叠加编号。编号不随拍摄画面一起放大或被裁掉。
- 单次成片使用第一段保留来源的完整正向画面尺寸作为固定画布；不同来源保持比例适配，允许画幅差异产生的留边，但取景本身不引入越界黑边。
- 预览与导出使用同一可见源画面区域；播放器容器留边不参与裁切坐标。
- 即使编号文字及底色完全透明，取景仍生效；不能把裁切实现挂在仅有编号才执行的路径上。
- 保留可用音轨、现有导出进度和取消行为；生成中配置来自不可变执行快照，后续编辑不能改变正在生成的取景。
- 修改取景成功保存后按现有 revision 规则标记旧成片过期；新成片提交成功前保留旧文件。

## 持久化兼容与配置变更

采用 schema 2，避免旧版本忽略新取景字段后重新写盘造成设置丢失。

- 支持读取 schema 1；缺失字段按未保存取景处理，既有范围、包含状态、编号和历史成片均保留。
- 读取兼容转换不触发 epoch 重置，也不因单纯打开任务而覆盖原文件；下一次正常成功持久化时原子写为 schema 2。
- 旧客户端对 schema 2 继续使用已有未知版本只读保护；不通过降级 schema 绕过保护。
- 校验器检查审核项与执行快照中的取景合法性；损坏文档与未来版本仍走既有保护流程。
- 只改编号样式保持所有取景；只改默认前后时长保留安全的已确认片段取景。
- 视频配置变化时，只有满足现有来源身份、时间元数据、打点集合和范围安全保留条件的确认项才保留取景；不能把旧坐标套到替换来源。
- “重置全部片段”同时清空已保存取景并恢复原画面，确认文案明确包含这一影响。
- `HighlightTaskPlanner` 的草稿转换、持久化转换、配置协调和执行快照均必须传递字段；旧组合确认 Store 不作为正式 App 新取景的第二权威来源。
- 取景中心与倍率不进入 Analytics、GlitchTip 或业务日志的自由数据。

## 验收与验证

1. 同源连续保留：A / 2.2× 自动带入下一段，确认后重开保持；排除走同样传递规则。
2. 在第九段改为 B / 3×、第十一段改为 C / 2.8×，后续连续审核正确延续，不回改前面的已保存片段。
3. 从底部手动跳到有保存值的目标，恢复其自身值；无保存值则原画面，不受刚离开片段影响。
4. 仅继承后手动跳走无需放弃提示且不写盘；主动修改后继续/放弃正确，保存失败不串片段。
5. 自动进入已有保存值的下一段，仅改变临时显示；未确认就退出重开，仍显示原保存值。
6. 恢复原画面不改变时间范围，随后自动导航沿用 1×；恢复默认时间范围不改变取景。
7. 跨来源、末项完成、会话退出和撤销不残留继承状态。
8. 撤销恢复完整取景和确认前状态，失败可重试；加载中撤销不会被旧加载覆盖。
9. 相同取景按旧规则合并，不同取景分开，重叠时间与汇总时长及实际导出一致。
10. 真实合成素材用不同位置的标识验证中心/边缘裁切、横竖屏旋转和多源切换，核对预览与导出可见区域；零透明度编号时仍有裁切。
11. 旧 schema 1 数据和历史执行快照可读，合法写入升级为 2；损坏值/未来版本保护、无变化事务和旧成片保留通过。
12. 最大字号下保留/排除、恢复和缩略图可达，VoiceOver 可调倍率/位置；顶部前后按钮确实移除，现有时间轴拖动与媒体加载回归通过。

验证采用纯几何/导航/规划/存储测试、真实媒体导出验证和必要 UI 回归。写规格本身不代表上述测试通过；实现后按证据更新 current 并归档。

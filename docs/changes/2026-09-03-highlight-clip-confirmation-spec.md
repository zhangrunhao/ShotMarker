# ShotMarker 片段确认持久化与连续审核规格

- 日期：2026-09-03
- 状态：设计已确认，尚未实现
- 目标版本：不绑定发布版本；本 Change 不修改版本号或构建号
- 设计基线：`main` / `d368622`
- 前置实现：[集锦片段审核与范围调整](../archive/2026-09/2026-09-02-highlight-clip-review-spec.md)

## 背景

当前集锦审核已经允许用户在图集和单片段编辑器之间切换，调整片段范围、保留或排除卡片，并在页面级“确认并生成”后把最终精确片段固化到 `HighlightJob`。在任务创建前，这些调整只存在于当前 `HighlightClipReviewViewModel` 的内存草稿中：返回图集后仍在，但退出整个流程、重新规划或终止 App 后不会恢复。

用户需要把“确认一个片段”与“创建整个集锦任务”分开：单片段确认成功后立即长期保存并自动进入下一个尚未确认的片段；以后再次选择完全相同的训练记录和视频组合时，恢复已确认结果。没有逐项确认的片段继续采用当前默认规划，不阻止生成集锦。

本 Change 在现有审核草稿和持久化任务之间增加独立的片段确认存储。它不把剪辑状态写入训练记录，也不依赖任务历史反推用户偏好。

## 当前实现差距

- `HighlightClipReviewItem` 的范围与 `isIncluded` 会在编辑时直接写回内存草稿。
- 单片段编辑器没有“确认片段”按钮，也没有编辑事务或逐片段确认状态。
- 审核图集只显示保留、排除和不可用状态，不能区分默认片段与长期确认片段。
- 审核草稿没有独立磁盘存储；只有页面级“确认并生成”创建的 `HighlightJob.confirmedSegments` 会持久化。
- 现有草稿指纹包含视频与全局前后时长，只用于判断当前内存草稿是否失效，不能识别跨启动可复用的训练/视频组合。
- “精调范围”区域默认展开。

## 已确认产品决定

1. 片段确认使用独立、版本化的本地 JSON 存储，不写入 `TrainingSession`，也不从 `HighlightJob` 历史恢复。
2. 点击“确认片段”后才把当前片段的范围与保留/排除状态长期保存；相同片段已有数据时原子替换。
3. 保存成功后自动打开当前卡片之后的第一个“默认”片段，跳过已经确认的片段；后面没有“默认”片段时返回审核图集。
4. 没有持久化确认项的卡片显示“默认”，不显示“待确认”，也不要求用户逐一确认。
5. 页面级“确认并生成”不要求所有卡片都已确认；最终结果由已确认片段与其余默认片段共同组成。
6. 已确认片段开始发生范围或保留状态变化时，当前编辑事务的状态变为“默认”；只有再次点击“确认片段”并写盘成功后才恢复“已确认”。
7. 用户有未确认改动时返回，必须提示“放弃本次调整？”；确认放弃后继续使用上次已确认值，原本没有确认值时继续使用默认值。
8. 复用要求训练记录内容、所选视频集合及视频选择顺序完全相同；同一批视频采用不同顺序时视为新组合。
9. 全局打点前/后时长不属于组合匹配键。修改全局默认时长后，已经确认的精确片段保持不变，新时长只重新计算尚未确认的默认片段。
10. 删除训练记录时同步删除它关联的片段确认记录；清除集锦任务不删除片段确认记录。
11. 片段确认数据在当前 App 安装内长期保留；App 卸载后由系统随沙盒一起删除。本 Change 不增加应用级云同步。
12. 单片段编辑器的“精确范围调整”默认收起，展开状态不持久化；播放预览、时间值和局部时间轴仍默认可见。
13. 原始训练记录、打点时间、视频内容和现有任务快照语义保持不变。
14. 本 Change 不增加 Analytics 事件或远端上传。

## 目标

1. 用户可以明确看到每张审核卡片当前使用默认值还是长期确认值。
2. 用户确认单个片段后，数据在 App 重启和重新进入相同训练/视频组合后仍可恢复。
3. 用户可以分多次完成审核；已经确认的片段恢复，其他片段保持默认。
4. 单片段编辑成为明确事务：确认才覆盖持久数据，放弃不会泄漏临时变化。
5. 确认成功后连续进入后续默认片段，减少反复返回图集的操作。
6. 全局默认前后时长变化不覆盖用户已经确认的精确片段。
7. 页面级生成继续支持直接采用全部默认结果，不强制机械式逐项确认。
8. 存储错误、损坏数据、未知版本和来源视频变化都不能静默套用错误范围。

## 非目标

- 不把逐片段确认改成生成集锦的强制门槛。
- 不在 App 启动时自动继续打开上次编辑器；只有用户再次选择匹配组合并进入审核时才恢复。
- 不支持跨设备、iCloud、自建服务器或账号同步片段确认数据。
- 不支持模糊匹配相似训练、相似视频或不同视频顺序。
- 不修改默认规划、0.1 秒规范化、1 秒最短片段、最终相邻合并或导出编号规则。
- 不拆分现有 `2–3` 等合并卡片内部的单个打点。
- 不增加片段重新排序、逐帧编辑、转场、变速、裁切画幅或音频编辑。
- 不改变片段序数样式的保存方式。
- 不为已经确认的片段增加锁定；用户仍可重新编辑并覆盖保存。
- 不从旧任务迁移或推断片段确认记录。
- 不在本 Change 中声明 VoiceOver 人工验收通过。

## 术语

### 审核组合

一条训练记录的完整内容，加上一组按选择顺序排列的来源视频。只有组合身份完全一致时才能复用片段确认记录。

### 默认片段

当前审核组合中没有对应持久化确认项的卡片。它的范围来自当前全局打点前/后时长，初始为保留。默认片段可以直接参与“确认并生成”，不代表错误或未完成。

### 已确认片段

用户点击“确认片段”且持久化成功的卡片。持久化项记录精确范围、关联打点及保留/排除状态，并在匹配组合中优先于默认规划。

### 编辑工作副本

单片段编辑器打开后创建的临时值。拖动、精调、恢复默认和切换保留状态都只修改工作副本；确认成功前不改变审核图集使用的数据或磁盘记录。

## 用户流程

### 首次进入

1. 用户打开训练记录并选择一个或多个视频。
2. App 完成现有视频校验、准备和稳定身份计算。
3. 用户进入片段审核。
4. App 计算审核组合身份，查询本地片段确认存储。
5. 没有匹配记录时，按当前全局前后时长生成全部默认卡片。
6. 图集卡片显示“默认”与当前保留状态。
7. 用户可以不编辑任何卡片，直接点击“确认并生成”。

### 确认单个片段

1. 用户打开默认或已确认卡片。
2. 编辑器从当前生效值创建工作副本。
3. 用户可以播放、拖动时间轴、使用 0.5 秒精调、恢复默认范围或改变保留状态。
4. 一旦工作副本与打开时值不同，编辑器状态显示为“默认”；磁盘中的旧确认项仍保持不变。
5. 用户点击底部“确认片段”。
6. App 规范化并验证工作副本，原子写入片段确认存储。
7. 只有写入成功后，审核图集才采用新范围与状态，并显示“已确认”。
8. App 停止当前播放和媒体请求，打开当前位置之后第一个“默认”片段。
9. 如果后面没有默认片段，则返回审核图集；不会从列表开头循环查找。

用户在默认片段上不做任何调整也可以点击“确认片段”。这会把当前默认范围作为明确确认值保存，并使其不再受以后全局前后时长变化影响。

### 放弃编辑

- 工作副本没有变化时，返回操作直接回到图集。
- 工作副本有变化时，返回操作显示“放弃本次调整？”。
- 选择“继续调整”时留在编辑器并保留工作副本。
- 选择“放弃”时丢弃工作副本：原先已确认的卡片恢复上次保存值和已确认状态；原先默认的卡片恢复当前默认值和默认状态。
- 放弃操作不得删除或改写已有确认项。

### 再次进入相同组合

1. App 使用训练内容与有序视频身份得到同一审核组合键。
2. 合法的持久化确认项恢复为已确认卡片，包括已确认排除的卡片。
3. 已确认项所关联的打点不再参加默认卡片生成。
4. 其余打点使用当前全局前后时长生成默认卡片。
5. 图集按原始匹配打点顺序交错展示已确认与默认卡片。
6. 进入审核页时保持图集总览，不自动推入编辑器；用户可以根据状态选择片段。

### 修改全局默认时长

- 审核组合身份不变。
- 已确认片段的精确范围、关联打点、保留状态和确认状态不变。
- 默认片段按新时长重新规划。
- 已确认项已经占用的打点不得再次出现在默认卡片中。
- 修改片段序数样式不影响确认记录或默认片段。

### 生成集锦

- “确认并生成”继续使用审核图集当前生效状态，不检查是否存在默认卡片。
- 已确认保留片段使用持久化精确范围。
- 已确认排除片段不进入最终结果，其关联打点也不作为默认片段重新出现。
- 默认片段使用当前默认范围和保留状态。
- 最终过滤、重新编号、相邻合并与 `ConfirmedHighlightSegment` 任务快照规则保持不变。
- 任务创建成功、失败、取消、清除或重启都不删除片段确认记录。

## 审核图集状态

每张卡片必须同时表达确认状态和生效的保留状态：

| 条件 | 可见状态 | 建议颜色与图标 |
| --- | --- | --- |
| 没有持久化确认项，当前保留 | `默认` | 橙色或次要强调色，`circle.dashed` |
| 有持久化确认项，当前保留 | `已确认 · 保留` | 绿色，`checkmark.circle.fill` |
| 有持久化确认项，当前排除 | `已确认 · 排除` | 灰色，`minus.circle.fill` |
| 来源当前不可用 | `视频不可用` | 红色，`exclamationmark.triangle.fill` |

来源不可用是当前错误状态，视觉优先级高于确认状态，但辅助功能文本仍应说明该卡片此前是默认还是已确认。确认状态不能只靠颜色表达。

卡片继续显示当前编号、缩略图、时长、最终合并提示和编辑入口。状态变化不得改变稳定卡片身份或让卡片在保存过程中突然消失。

图集不显示完成百分比，也不把默认片段描述为未完成。页面级“确认并生成”沿用现有有效片段和来源可用性门槛，不新增“全部确认”的禁用条件。

## 单片段编辑器

### 页面结构

编辑器保持当前播放预览、时间值、局部胶片时间轴、播放按钮、保留状态和恢复默认范围。新增：

- 当前工作副本的“默认”或“已确认”状态；
- 底部固定的“确认片段”按钮；
- 持久化进行中与失败反馈；
- 未确认改动返回提示。

“确认片段”放在安全区域底部，内容滚动时仍可见，触摸目标至少 44 点。保存期间按钮显示进行中状态并禁用重复提交。

### 精确范围调整默认收起

现有三组 0.5 秒按钮放入标题为“精确范围调整”的 `DisclosureGroup`：

- 起点 `-0.5s` / `+0.5s`；
- 终点 `-0.5s` / `+0.5s`；
- 整体 `-0.5s` / `+0.5s`。

每次创建编辑器时展开状态初值为 `false`，离开后不持久化。局部时间轴、手柄、播放游标、时间值、播放按钮、保留状态与“恢复默认范围”不放入该折叠区域。

### 编辑事务

编辑器不得再直接修改审核图集持有的生效 `HighlightClipReviewItem`。工作副本至少包含：

- 打开时的生效范围；
- 当前临时范围；
- 打开时的保留状态；
- 当前临时保留状态；
- 打开时是否已有持久化确认项；
- 是否存在有效变化；
- 保存状态和错误。

拖动、精调和恢复默认继续使用现有统一范围约束与 0.1 秒规范化。播放控制器和时间轴读取工作副本，不读取尚未更新的图集卡片。

已确认卡片打开但没有变化时保持“已确认”。发生任何有效范围或保留状态变化后，工作状态显示“默认”；保存失败时仍保持默认工作状态和当前值，允许重试。放弃后恢复打开时的持久化状态。

“恢复默认范围”只改变当前工作副本，不自动删除确认项、不自动写盘，也不影响保留状态。用户随后点击“确认片段”时，把恢复后的范围作为新的已确认值覆盖保存。

### 确认事务顺序

点击“确认片段”必须按以下顺序执行：

1. 防止重复提交并暂停播放器。
2. 按现有规则把范围规范化到 0.1 秒和 timescale 600 语义。
3. 验证来源视频、边界、最短长度、关联打点和保留状态。
4. 生成或替换当前审核组合下的持久化确认项。
5. 原子写入存储文件。
6. 写入成功后才把结果发布给审核 ViewModel、刷新汇总和缩略图。
7. 清除工作副本保存错误，标记卡片已确认。
8. 取消当前媒体请求并执行下一默认片段导航。

步骤 2–5 任一失败时不得更新图集、不得关闭编辑器、不得导航到下一片段。页面显示可重试且不含内部路径或标识符的错误信息。

### 来源不可用与排除

- 来源暂时加载失败时允许重试，工作副本保留。
- 来源永久不可用时，保留状态的工作副本不能确认。
- 用户可以选择“排除并确认片段”；该动作把 `isIncluded = false` 交给同一个确认事务，保存成功后自动进入下一默认片段。
- 用户选择返回重新选视频时，未确认工作副本按放弃规则处理。

## 审核组合身份

组合身份必须由可编码、可比较的完整结构生成，不能只依赖随机 UUID、展示编号、临时文件 URL 或哈希值本身。

### 训练身份

训练身份包含：

- `TrainingSession.id`；
- `startedAt`；
- `endedAt`；
- 按 `markedAt`、再按打点 UUID 排序的全部 `{ id, markedAt }`。

日期统一规范为 Unix epoch 毫秒整数后参与比较。相同 UUID 但起止时间、打点集合或任一打点时间变化时都视为不同训练内容，不复用旧确认项。

### 视频身份

视频身份数组严格保留用户选择顺序。每个元素包含：

- 稳定来源身份；
- 规范化后的拍摄时间；
- 规范化后的时长。

拍摄时间使用 Unix epoch 毫秒整数；时长使用 timescale 600 的整数 tick。这样可以消除同一媒体被 AVFoundation 重新读取时无意义的浮点尾差，但实际元数据变化仍会产生不同组合。

稳定来源身份按以下优先级取得：

1. PhotoKit 或 PhotosPicker 提供稳定资源标识时，保存带类型前缀的资源标识。
2. 只能取得本地临时文件时，在后台以流式读取计算完整文件 SHA-256，保存带类型前缀的内容摘要。

不得使用临时复制 URL 作为持久化身份。内容摘要计算不得一次把整个视频载入内存，也不得写入日志或 Analytics。

### 组合摘要

实现可以对规范化后的完整组合结构计算 SHA-256 作为索引，但存储记录必须同时保存完整结构，并在命中摘要后执行结构相等检查。视频顺序不同、训练内容不同或视频元数据不同都不能复用。

全局前后时长和 `MarkerLabelStyle` 明确不进入组合身份。

## 持久化数据模型

存储位置：

~~~text
Application Support/ShotMarker/highlight-clip-reviews.json
~~~

语义模型至少包含：

~~~swift
struct HighlightClipReviewStoreDocument: Codable, Equatable {
    let schemaVersion: Int
    var records: [PersistedHighlightClipReview]
}

struct PersistedHighlightClipReview: Codable, Equatable {
    let combination: HighlightClipReviewCombination
    var confirmedItems: [PersistedHighlightClipConfirmation]
    let createdAt: Date
    var updatedAt: Date
}

struct PersistedHighlightClipConfirmation: Codable, Equatable {
    let videoIdentity: PersistedVideoIdentity
    let markerIDs: [UUID]
    let defaultStart: TimeInterval
    let defaultDuration: TimeInterval
    let start: TimeInterval
    let duration: TimeInterval
    let isIncluded: Bool
    let confirmedAt: Date
}
~~~

具体命名可以在实施计划中按项目风格细化，但以下契约不可改变：

- 根文档 `schemaVersion = 1`。
- 一条记录对应一个精确审核组合；同一训练可以拥有多个不同视频组合记录。
- 片段确认身份由稳定视频身份和按原始顺序排列的非空 `markerIDs` 共同构成。
- 同一记录内一个打点只能由一个确认项占用。
- 显示编号、分母、缩略图、胶片帧、播放器状态、临时 URL 和保存错误不持久化。
- `defaultStart/defaultDuration` 保存该卡片形成时的默认基线，供以后“恢复默认范围”使用；全局设置变化不改写已确认卡片的基线。
- 首次确认默认卡片时保存它当前的默认基线；再次确认已有确认项时保留原默认基线，只替换当前范围、保留状态和确认时间。
- `start/duration` 使用与现有审核和任务快照相同的 0.1 秒规范化与 timescale 600 语义。
- 已确认排除项也必须保存范围和默认基线，确保以后恢复保留时仍有确定值。
- 更新现有片段确认时替换同身份项并更新 `confirmedAt` 与记录 `updatedAt`，不能产生重复项。
- 存储不包含训练或视频内容本身，只包含匹配和恢复所需的本地身份与时间值。

## 恢复与默认规划

恢复过程必须由无 UI 的规划/合并单元完成，不能在 SwiftUI View 中拼接：

1. 使用当前训练与有序视频构建完整组合身份。
2. 加载完全匹配的版本 1 记录；没有匹配时生成全部默认草稿。
3. 验证每个确认项的视频身份、打点存在性、打点唯一性、范围、默认基线与视频边界。
4. 合法确认项占用其全部关联打点，并以保存的精确范围和保留状态重建已确认卡片。
5. 从当前训练打点中排除已经被合法确认项占用的打点。
6. 对剩余打点使用当前全局前后时长运行默认规划，生成默认卡片。
7. 将两类卡片按原始匹配打点顺序组合；同一时间的稳定次序使用打点 UUID 和视频选择顺序打破平局。
8. 使用现有汇总逻辑计算编号、保留/排除数量、最终相邻合并和预计总时长。

已确认卡片不能因为新的默认范围与它重叠而被默认规划覆盖或拆开。默认规划也不能重新生成已确认排除项所关联的打点。

语义损坏的单个确认项不套用；其打点回到当前默认规划，并显示一次非阻塞的“部分已保存片段无法恢复，已使用默认范围”提示。合法确认项继续恢复。日志只记录封闭错误类别和数量，不记录组合内容或本地资源标识。

## Store 边界与写入规则

新增专用 Store protocol 及磁盘/内存实现。职责包括：

- 加载精确审核组合；
- 原子 upsert 单个确认项；
- 删除指定训练记录的全部组合；
- 根据当前训练记录集合清理孤立或内容已失效的组合；
- 提供可测试的缺失文件、损坏文件和未知版本行为。

Store 不负责默认规划、UI 导航、视频播放、任务创建或训练记录保存。

磁盘写入必须串行化并使用同目录临时文件加原子替换。多个快速确认不能互相覆盖；每次 upsert 都以最新已加载文档为基础合并。确认按钮保存期间禁用，重复点击不得产生第二次导航或重复确认项。

文件不存在表示从未保存，返回空文档。根 JSON 无法解码时先把原文件移动为 `highlight-clip-reviews.corrupt-<UTC 时间戳>.json` 恢复副本，再创建新的版本 1 文档，并向当前流程报告恢复提示。遇到高于当前实现的未知 `schemaVersion` 时不得降级覆盖原文件；读取按空确认处理，写入失败并提示需要更新 App。

## 生命周期与清理

- 片段确认记录不设 TTL，也不因生成集锦、任务完成、任务失败或用户清除任务而删除。
- 用户删除训练记录后，删除所有 `TrainingSession.id` 相同的审核组合记录。
- 导入替换、合并或其他训练保存使同一 ID 的训练内容变化时，删除与当前训练身份不再完全一致的旧记录。
- 每次训练列表成功载入后可以执行一次轻量 reconciliation，清理此前因写入失败留下的孤立记录。
- 训练记录保存成功但确认记录清理失败时，不回滚训练删除；记录本地错误并在下次 reconciliation 重试。
- 来源视频从照片库删除时暂不主动删除确认记录；该组合无法再次完整选择，不会误命中其他视频。
- App 卸载后数据随沙盒删除；本 Change 不实现导入、导出或跨设备迁移确认记录。

## 组件边界

### 持久化模型与 Store

新增独立的可编码模型、组合身份构建器和 `HighlightClipReviewStore`。文件 I/O 与内容摘要计算不得放在 SwiftUI View 中。测试使用内存 Store 或临时文件注入。

### SelectedTrainingVideo 身份

运行时视频模型或相邻包装类型需要同时表达：

- 当前播放、准备和任务创建使用的运行时 `videoID`；
- 片段确认匹配使用的稳定持久身份。

两者不能混用。PhotoKit 视频的任务来源仍使用现有 local identifier；临时文件任务仍按现有规则复制到任务目录。

### HighlightClipReviewPlanner

在现有默认草稿与最终汇总职责旁增加纯函数恢复步骤：验证持久化确认项、移除已占用打点、生成剩余默认项并稳定交错排序。它不执行磁盘 I/O。

### HighlightClipReviewViewModel

负责加载后的生效卡片、确认状态、汇总、持久化协调和下一默认片段选择。它只在 Store 写入成功后应用确认结果。

ViewModel 必须提供可独立测试的导航结果，例如：

~~~swift
enum HighlightClipConfirmationNavigation: Equatable {
    case open(itemID: UUID)
    case returnToReview
}
~~~

具体 API 可以调整，但不能把“查找下一默认片段”的规则散落在多个 View。

### HighlightClipEditorViewModel 或编辑事务

单片段工作副本、脏状态、保存状态、放弃判断和播放范围应由独立可测试状态单元持有。可以新增专用 ViewModel，也可以在审核 ViewModel 中建立明确 editor transaction；不得继续让 View 直接改写共享卡片。

### HighlightClipEditorView

负责展示工作副本、默认收起的精确范围调整、底部确认按钮、保存错误和放弃提示。保存或导航决定来自状态单元，不直接写 JSON。

### HighlightClipReviewView

负责图集中的默认/已确认状态、编辑器导航和页面级“确认并生成”。它不要求所有卡片确认，也不实现持久化匹配算法。

### TrainingSessionHighlightView

负责从当前训练、所选视频和设置准备恢复输入，并注入 Store。现有大型 View 不应继续承载 JSON 编解码或片段身份算法。

### 训练记录删除链路

训练列表的删除、合并和导入替换在训练数据保存成功后调用确认 Store 清理。清理接口按训练 ID 和当前完整训练集合工作，确保训练事实存储与确认存储保持松耦合。

## 数据流

~~~text
TrainingSession + ordered SelectedTrainingVideo[]
                    ↓ 规范化稳定身份
        HighlightClipReviewCombination
                    ↓ 精确匹配
       HighlightClipReviewStore (JSON v1)
                    ↓ 合法已确认项
      ┌─────────────┴─────────────┐
      ↓                           ↓
已确认项占用的打点          其余训练打点 + 当前默认时长
      ↓                           ↓
保存范围/保留状态             默认审核规划
      └─────────────┬─────────────┘
                    ↓ 稳定交错排序
        HighlightClipReviewViewModel
           ├─→ 图集状态与汇总
           └─→ 编辑工作副本
                    ↓ 确认片段
        原子 upsert JSON → 应用结果 → 下一默认片段
                    ↓ 页面级确认并生成
          ConfirmedHighlightSegment[]
                    ↓
               HighlightJob
~~~

持久化确认记录和 `HighlightJob.confirmedSegments` 是两个不同生命周期的数据：前者用于以后复用审核选择，后者是一次具体导出任务不可变的执行快照。

## 错误与并发处理

### 身份准备失败

- PhotoKit 标识可用时不计算内容摘要。
- 临时文件摘要在后台流式计算，失败时沿用现有视频读取错误路径，不生成不稳定的持久身份。
- 身份尚未完成时不进入审核页，继续显示视频准备状态。

### 加载失败

- 没有文件或没有匹配记录：正常使用全部默认片段。
- 个别确认项语义无效：仅该项回退默认，并显示一次非阻塞提示。
- 整份 JSON 损坏：保留恢复副本，当前组合使用默认片段；后续确认写入新文档。
- 未知更高版本：不覆盖原文件，确认按钮显示可操作错误。

### 保存失败

- 保留编辑工作副本、播放器位置和当前页面。
- 图集生效值与旧磁盘数据保持不变。
- 不标记已确认、不刷新到下一片段、不创建任务。
- 用户可以重试或放弃本次调整。

### 来源变化

- 视频身份、拍摄时间或时长变化会产生新组合，不套用旧记录。
- 当前来源在确认前变为不可读时，保留状态不能确认；排除状态可以通过“排除并确认片段”保存。
- 页面级生成继续执行现有提交前来源复核。

### 并发

- Store 写入在单一隔离域内串行执行。
- 同一片段的重复确认采用最后一次成功事务，但一次按钮动作只能产生一次写入和一次导航。
- 页面退出或 Task 取消不能让“磁盘已成功、内存仍显示旧值”长期存在；取消边界放在原子写入之前，写入开始后完成内存发布或在下次加载时从磁盘恢复。

## 兼容与迁移

- 旧版本没有 `highlight-clip-reviews.json`，首次运行直接视为空存储，不需要迁移。
- 本 Change 不修改 `training-sessions.json`、Watch 同步载荷、`highlight-jobs.json` 或 `clipPlanVersion = 1` 契约。
- 现有训练记录、任务和默认设置继续解码。
- 旧任务不能自动变成可复用确认项，因为任务中的最终合并片段不能无歧义恢复到审核卡片。
- schema version 1 的模型只做向后兼容解码；未来字段演进必须提升或明确兼容策略，不能猜测未知版本。
- 当前内存草稿不会在升级时迁移；只有升级后成功点击“确认片段”的项目进入新存储。

## 性能与资源

- PhotoKit 标识路径不增加视频内容读取。
- 只有缺少稳定资源标识的临时文件计算完整 SHA-256；使用固定大小缓冲区流式读取，不把整个视频载入内存。
- 同一次视频选择生命周期缓存已经计算的稳定身份，不能为每张卡片重复哈希同一视频。
- Store 按组合索引读取，单次确认只更新一条组合记录；不得同步生成缩略图或重新读取视频内容。
- JSON 写入和哈希不阻塞主线程；UI 只在 MainActor 发布状态。
- 图集缩略图、胶片帧和播放器继续使用现有有界内存缓存和取消规则。

## 隐私、日志与数据边界

- 片段确认文件保存在 App Application Support 中，不上传 ShotMarker 服务、Analytics 或 GlitchTip。
- 文件包含训练/视频匹配所需的本地标识、打点 ID 与时间范围，但不包含视频帧、音频、缩略图、文件名或媒体内容。
- PhotoKit local identifier 和内容 SHA-256 不得进入日志、错误文案、Analytics 或 GlitchTip metadata。
- 日志只允许记录：是否命中组合、恢复/默认/确认项数量、保存成功与封闭错误类别、清理记录数量。
- 本 Change 不增加 Analytics 事件，现有四事件契约不变。
- 原始训练和视频内容仍不上传；标准系统设备备份行为不等于应用级云同步，本 Change 不新增自建同步能力。

## 辅助功能与动态字体

- 图集卡片可读出片段编号、时长、默认或已确认状态、保留或排除状态，以及来源错误。
- “确认片段”按钮提供保存中的状态和保存失败提示，不能只依靠颜色或进度动画。
- “精确范围调整”DisclosureGroup 读出展开/收起状态；其中每个 0.5 秒按钮保留现有明确名称和值域反馈。
- 放弃提示的“继续调整”和“放弃”具有明确语义，默认不选择破坏性动作。
- 最大 Dynamic Type 下状态文案允许换行，底部按钮和卡片入口保持至少 44 点。
- 本 Change 要求自动化检查可访问名称与状态，但不把 VoiceOver 人工流程作为完成门槛，也不得记录为已通过。

## 自动测试

### 组合身份

- 完全相同训练内容与同序视频产生相同组合。
- 视频集合相同但顺序不同不匹配。
- 训练 ID 相同但起止时间、打点 ID 或打点时间变化不匹配。
- 视频稳定身份、拍摄时间或规范化时长变化不匹配。
- 全局前后时长和序数样式变化不改变组合身份。
- 日期毫秒与时长 timescale 600 规范化消除无意义浮点尾差。
- PhotoKit 身份优先于内容摘要；临时 URL 不参与身份。
- 临时文件内容相同产生相同 SHA-256，不同内容不匹配，计算使用有界缓冲区。

### Store

- 缺失文件返回空版本 1 文档。
- 保存一个确认项后重新创建 Store 仍能恢复。
- 再次确认同一视频和打点组合会替换旧值，不产生重复项。
- 不同训练或不同视频组合互不覆盖。
- 部分确认可以独立往返；默认项不写入 JSON。
- 已确认排除项完整往返范围与状态。
- 原子写入失败保留旧文件和旧确认值。
- 快速连续保存不会丢失先前成功项。
- 语义无效项仅自身回退默认。
- 根 JSON 损坏时保留恢复副本并建立新文档。
- 未知更高 schema 只读失败且不覆盖原文件。
- 删除训练记录清除其全部组合，不影响其他训练。
- reconciliation 清除训练内容已变化或已经删除的孤立记录。

### 恢复规划

- 没有记录时结果与当前默认规划完全一致。
- 已确认项恢复精确范围、默认基线、关联打点和保留状态。
- 已确认打点不再出现在默认卡片。
- 已确认排除项关联打点不会重新成为默认卡片。
- 修改全局前后时长只重新计算未确认片段。
- 已确认与默认卡片按原始打点顺序稳定交错。
- 多视频仍遵守原选择顺序和单卡片单视频边界。
- 损坏确认项的打点安全回退当前默认规划。
- 恢复后的汇总与页面级任务快照使用同一最终规划结果。

### 编辑事务与 ViewModel

- 打开默认和已确认卡片会建立正确工作副本。
- 拖动、精调、恢复默认和保留切换只修改工作副本。
- 已确认工作副本发生有效变化后显示默认状态。
- 未变化返回不弹提示；有变化返回弹放弃提示。
- 放弃默认卡片恢复当前默认值，放弃已确认卡片恢复旧确认值。
- 保存成功后才更新图集、确认状态、汇总和缩略图。
- 保存失败保留工作副本、旧图集值和旧磁盘值。
- 重复点击只产生一次确认和一次导航。
- 确认后跳过后续已确认卡片，打开第一个后续默认卡片。
- 后续没有默认卡片时返回图集，不从开头循环。
- 默认卡片存在时页面级“确认并生成”仍可用。
- 已确认排除项不阻止其余有效片段生成。
- 来源不可用时保留确认被阻止，“排除并确认片段”成功保存并导航。

### UI 与集成

- 图集正确显示默认、已确认保留、已确认排除和视频不可用状态。
- 状态具有独立可访问文本，不只依靠颜色。
- 底部“确认片段”在滚动和最大 Dynamic Type 下可见且可操作。
- “精确范围调整”每次进入默认收起，展开后全部 0.5 秒控件可用，重新进入仍收起。
- 确认按钮成功后实际打开预期片段；最后一个后续默认片段确认后返回图集。
- 训练删除、导入替换与合并完成后触发确认记录清理。
- 清除或重启集锦任务不删除片段确认记录。
- 现有 `HighlightJob` fixture、Runner 和任务恢复测试继续通过。

## 人工验收

使用至少一条包含普通卡片和合并卡片的训练记录，以及两个可交换选择顺序的视频：

1. 首次选择视频进入审核，确认所有卡片显示“默认”，并可直接“确认并生成”。
2. 调整第一张片段并确认，验证列表显示“已确认 · 保留”，自动打开后续第一个默认片段。
3. 让中间卡片保持已确认，再从更早卡片确认，验证自动跳过它。
4. 确认最后一个后续默认片段，验证返回图集而不是循环到开头。
5. 退出流程并终止 App，重新选择相同训练和同序视频，验证已确认范围和状态恢复。
6. 只确认部分片段，验证重新进入后其余卡片仍为默认且可以直接生成。
7. 修改全局前后时长，验证已确认片段不变，默认片段使用新范围。
8. 使用同一批视频但交换顺序，验证不恢复旧确认项。
9. 编辑已确认片段，验证状态变为默认；不确认返回时出现放弃提示，放弃后恢复旧确认值。
10. 编辑已确认片段并再次确认，验证旧持久化值被替换。
11. 把一个片段设为排除并确认，验证重启后仍显示“已确认 · 排除”，且打点不重新出现在默认片段。
12. 模拟存储写入失败，验证留在编辑器、工作副本不丢失且没有前进导航。
13. 验证精确范围调整默认收起，展开可用，重新进入后再次收起。
14. 删除训练记录后重新导入不同内容，验证旧确认项不会错误恢复。
15. 清除已生成任务后重新进入相同组合，验证片段确认记录仍存在。
16. 使用最大 Dynamic Type 检查列表状态、放弃提示和底部确认按钮。

## Definition of Done

- [ ] 相同训练内容与同序视频组合可以跨 App 启动恢复逐片段确认。
- [ ] 每次“确认片段”原子替换当前片段持久化值，失败时不更新 UI 或导航。
- [ ] 图集准确区分默认、已确认保留、已确认排除和来源不可用。
- [ ] 已确认片段重新编辑必须再次确认；放弃编辑恢复旧持久化值。
- [ ] 确认成功后打开后续第一个默认片段，没有时返回图集。
- [ ] 默认片段无需逐项确认即可参与页面级生成。
- [ ] 修改全局前后时长不覆盖已确认片段，只重算默认片段。
- [ ] 精确范围调整默认收起且展开状态不持久化。
- [ ] 删除或替换训练记录会清理无法再匹配的确认记录，任务清理不会删除它们。
- [ ] 持久化文件版本化、原子写入，并安全处理损坏和未知版本。
- [ ] 原始训练、任务兼容、隐私和 Analytics 契约保持不变。
- [ ] 自动测试、完整构建与约定人工验收全部按真实证据完成。

# ShotMarker 产品需求文档

日期：2026-05-01
状态：草案
技术方向：SwiftUI

## 产品概述

ShotMarker 面向进行投篮训练的篮球爱好者。用户在训练时使用手机拍摄或导入训练视频，使用 Apple Watch 在关键投篮时刻打点；训练结束后，手机端根据视频开始时间和手表端时间戳自动剪辑训练集锦，并保存到系统相册。

产品核心价值是减少训练复盘的视频整理成本，让用户不需要手动拖动长视频，也能快速得到每次投篮前后的小片段。

## 目标用户

- 经常进行个人投篮训练的篮球爱好者。
- 希望保留训练片段、复盘动作或分享训练成果的用户。
- 训练时愿意佩戴 Apple Watch，并能在投篮或命中后快速打点的用户。

## 产品感受

- 专业：流程稳定、剪辑结果可信、时间对齐逻辑清晰。
- 克制：界面不做社交化和娱乐化堆叠，优先提供导入、打点、选择、生成这条主路径。

## P0 范围

### 手机端视频导入

- 支持从苹果相册导入带有开始时间的视频。
- 导入后形成本地视频列表。
- 视频列表至少展示视频缩略图、文件名或导入时间、视频开始时间、时长。

### 手机端本地视频列表

- 用户可以查看已经导入到应用内的视频。
- 用户可以选择一个视频进入后续剪辑流程。
- P0 暂不要求云同步、标签分类或复杂筛选。

### 手表端打点

- Apple Watch 端提供快速打点入口。
- 每次打点记录当前绝对时间。
- 按日期形成时间戳文件，便于手机端按训练日期选择。

### 手机端时间戳文件列表

- 手机端可以查看手表端生成的时间戳文件列表。
- 时间戳文件至少展示日期、打点数量、最后更新时间。
- 用户可以选择一个时间戳文件用于剪辑。

### 视频与时间戳匹配

- 用户选中一个视频，再选择一个时间戳文件。
- 系统根据视频开始时间和时间戳中的绝对时间计算每个打点在视频内的相对时间。
- 只处理落在视频时长范围内的打点。

### 自动剪辑

- 默认每个打点生成一个片段：打点前 10 秒到打点后 3 秒。
- 如果片段开始时间早于视频开始，则从视频第 0 秒开始。
- 如果片段结束时间超过视频结束，则截断到视频结束。
- 多个片段按时间顺序合成为一个集锦视频。

### 保存到相册

- 集锦视频生成后自动保存到系统相册。
- 保存前需要处理相册权限。
- 保存失败时应给出明确错误提示，并允许用户重试。

## P1 范围

- 支持导入不带开始时间的视频。
- 选中视频和时间戳文件后，允许用户手动调整时间戳整体偏移。
- 允许用户调整每个打点前后剪辑时长，例如从默认的前 10 秒、后 3 秒改为自定义值。

## P2 范围

- 手机端直接录制视频，并在录制过程中实时剪辑成为片段。
- 支持片段选择、组合和过场动画。
- 支持多机位同时剪辑。
- 加入登录、社区分享等在线能力。

## 核心用户流程

### P0 主流程

1. 用户开始投篮训练并录制视频。
2. 用户训练过程中在 Apple Watch 上为关键时刻打点。
3. 训练结束后，用户在手机端导入带开始时间的视频。
4. 用户在手机端选择目标视频。
5. 用户选择同一天或对应训练的时间戳文件。
6. 应用根据视频开始时间和打点时间自动生成剪辑任务。
7. 应用导出集锦视频并保存到相册。

### P1 对齐流程

1. 用户选择视频和时间戳文件。
2. 如果视频缺少开始时间，用户手动设置视频开始时间或调整时间戳偏移。
3. 用户预览片段命中情况。
4. 用户确认后生成集锦。

## 非功能要求

- P0 优先本地处理，不依赖登录和服务端。
- 视频和打点数据默认保留在设备内，降低隐私风险。
- 剪辑结果应可解释：用户能知道哪些打点被纳入、哪些被忽略。
- 时间计算需要处理时区、夏令时和设备时间误差，内部应优先使用绝对时间。
- UI 风格保持克制，主流程中减少非必要入口。

## 待确认问题

- 手表端打点的最佳交互：单按钮、并发症入口，还是训练会话内入口。
- 打点时刻代表投篮出手、命中、还是用户主观认为值得保留的时刻。
- 时间戳文件同步方式：WatchConnectivity 实时同步，还是训练后批量同步。
- 视频开始时间的来源优先级：相册 metadata、PHAsset creationDate、文件 metadata，还是用户手动输入。
- 多个打点片段重叠时，P0 是否直接合并重叠片段。
- 生成集锦是否需要保留原视频音频。
- P0 是否需要提供生成前预览，还是直接生成并保存。
